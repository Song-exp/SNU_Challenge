# 서울대 AI 챌린지 통합 학습 가이드 — [문장·이미지·모델 융합 및 코드 해설]

본 문서는 서울대학교 AI 챌린지 프로젝트의 **문장 분석(NLP), 이미지 전처리(CV), 그리고 모델 학습 및 추론(Deep Learning)**이라는 세 가지 핵심 축이 어떻게 유기적으로 결합하여 최종 코드로 도출되었는지 그 개발 이력과 설계 개념을 상세히 해설합니다.

병철 님, 작성하신 학습 코드와 추론 코드는 캐글(Kaggle) T4 GPU 제약 환경(VRAM 16GB, 12시간 시간 제한)에서 8B 규모의 거대 비전-언어 모델(Qwen3-VL-8B)을 터뜨리지 않고 완주시키기 위한 최상급 엔지니어링 테크닉이 집약된 스크립트입니다. 어려운 파이토치(PyTorch) 테크니컬 구문들을 하나씩 짚어가며, "이 코드가 정확히 무슨 일을 하고, 왜 이렇게 짰는지" 전문성과 직관적 명쾌함을 둘 다 잡아서 파트별로 풀어드릴게요!

## 1. 세 축의 융합 과정 (Spatio-Temporal Fusion Timeline)

```
[문장 분석 파트]  ────────┐
(통사 구조 & AI 모호성)    │
                          ▼
[이미지 전처리 파트] ───► [하이브리드 데이터셋 구성] ───► [LoRA 학습 및 K4 우도 추론]
(CLIP 분할 & 기하 궤적)      (Soft Prompting 내재화)        (Position Bias 소거 및 완주)
                          ▲
[딥러닝 학습/추론] ───────┘
(KV-Cache 복제 & RoPE)
```

### A. 문장 분석 (NLP) 파트의 진화
1. **단어 매칭 (초기)**: 캡션 문장에 단순히 "zoom" 또는 "left"와 같은 특정 단어가 들어있는지만을 정규식으로 판별했습니다.
2. **SpaCy 구문 분석 트리 (중기)**: 단어 매칭만으로는 시간의 전후 관계를 모호하게 서술한 복잡한 문장을 분석하기 어려웠습니다. 이에 SpaCy 라이브러리의 의존성 구문 분석(Dependency Parsing)을 활용하여 문장을 **Type-1 (단일 절)**, **Type-2 (복합 종속)**, **Type-3 (대등 병렬)**로 3분류하고 주어/동사 개수를 정량화했습니다.
3. **다차원 직교 플래그(N1~N7) 및 AI 점수**: 문장의 시간적 왜곡과 모호성을 점수로 계량화하기 위해 **Ambiguity Index (AI)** 공식을 설계하여 `ai_score`로 척도화했습니다.

### B. 이미지 전처리 (CV) 파트의 진화
1. **픽셀 MSE (Adjacent MSE)**: 픽셀 값 변화를 이용해 장면 단절을 구하려 했으나, 카메라 흔들림(Whip Pan)을 장면 전환으로 오판하는 문제가 컸습니다.
2. **CLIP 기반 의미론적 분할**: OpenAI CLIP(ViT-B/32) 이미지 특징 코사인 거리를 활용하여 물리 노이즈에 왜곡되지 않는 **0.20 절대 임계값 기반 장면 분할 알고리즘**을 수립하고, **유니온-파인드(Union-Find)** 자료구조로 이미지 세트의 탐색 공간을 $4! = 24$에서 $4$로 줄였습니다.
3. **OWL-ViT Open-Vocabulary 피사체 트래킹**: 고정 클래스만 잡는 YOLOv8의 한계를 넘어, Gemma가 뽑아낸 특수 도구 명사를 OWL-ViT에 동적 입력하여 피사체 중심 $(x,y)$과 면적비($R_{\text{bbox}}$)를 마스킹 기법과 함께 추적했습니다.

### C. 딥러닝 학습 및 추론 파트의 융합
* **통찰**: "추론 단에서 비전 모델(OWL-ViT, CLIP)과 언어 모델(Gemma, Qwen)을 동시에 구동하면 Kaggle의 T4 GPU가 **VRAM OOM**으로 터지고, 24시간 내에 819문항을 풀지 못해 **시간 초과 실격**이 발생한다."
* **해결 (Soft Prompting 위임)**: 
  * 이미지/문장 분석기의 결과(Z-Score, 씬 경계, 객체 물리 궤적)를 학습 데이터 구성 단계에서 프롬프트에 녹여 미세조정(Fine-Tuning)함으로써, 8B VLM의 Attention 레이어가 시공간 기하학적 정보(Spatial Prior)를 스스로 가중치에 녹여내도록 학습시켰습니다.
  * 추론 시에는 무거운 비전 트래커를 모두 걷어내고, 오직 **Qwen3-VL 8B 단독 모델**에 **우도 K4 TTA** 기법만을 씌워 초고속 고정밀 추론을 달성했습니다.

## 2. 학습 코드 (`FINAL_8B_v2.py` / `train.py`) 핵심 로직 해설

### ① 데이터 준비 & 강건 셔플링 (`hard_perm` 함수)
* **무슨 일을 하나요?**: 
  * 단순히 4장의 순서를 무작위로 섞어 학습시키는 게 아니라, CLIP 모델이 측정한 "서로 너무 비슷해서 구분하기 어려운 이미지 조합(CLIP 유사쌍)"의 선후 관계를 인위적으로 뒤흔들고 파괴한 **가장 꼬여있는 난해한 순열**을 계산해 냅니다.
  * 동일 장면에 속한 프레임들의 상대적 순서가 깨지도록 유도하는 조건에 **`10`의 패널티 가중치(10x Multiplier)**를 곱해 최악의 순서 후보(Hard Negative)를 데이터셋에 주입합니다.
* **왜 이렇게 짰나요?**:
  * 모델에게 쉬운 샘플만 주면 이미지의 겉모습(색상, 배경)만 보고 대충 정답을 찍는 나쁜 습관(Short-cut Learning)이 생깁니다.
  * 물리적으로 가장 선후 관계를 구분하기 힘든 순열(`hard_perm`)을 정답과 대조하게 만들어, 모델이 피사체의 세밀한 물리적 위치 변화와 장면 경계선을 집중 학습(Hard-sample Mining)하도록 강제했습니다.

### ② 4bit QLoRA & 메모리 절감
```python
quant = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.float16,
)
```
* **무슨 일을 하나요?**: 
  * 80억 개 파라미터(8B)의 거대 가중치를 4비트(nf4)로 압축해 메모리에 올리고, 연산할 때만 `float16` 정밀도로 살짝 끌어올려 계산합니다.
* **왜 이렇게 짰나요?**: 
  * Qwen3-VL 8B 모델을 원본(16비트) 그대로 올리면 가중치만 16GB를 차지해 16GB VRAM 단일 GPU 환경에서는 학습이 아예 불가능합니다. 
  * 4비트 양자화를 적용하면 VRAM 점유율이 5~6GB 수준으로 뚝 떨어져 T4 GPU 한 장에서도 여유롭게 학습할 수 있습니다.

### ③ 캐글 12시간 튕김 방지 & 백그라운드 자동 복원
```python
if time.time() - t0 > CFG["max_seconds"]:
    save_ckpt(step)
    raise KeyboardInterrupt
```
* **무슨 일을 하나요?**: 
  * 100스텝마다 가중치(`adapter_model.safetensors`), 최적화 상태(`optim.pt`), 현재 스텝(`meta.json`)을 세트로 저장하다가, 11.3시간이 넘어가면 세션이 꺼지기 전에 자발적으로 멈추고 안전하게 저장합니다.
* **왜 이렇게 짰나요?**: 
  * 캐글은 12시간이 지나면 작업이 강제 종료되어 모든 데이터가 날아갑니다. 
  * 다시 'Run All'을 누르면 코드 상단의 `restore_ckpt_from_input()`이 이전 저장본을 감지해 가장 최근 스텝(예: Step 977)부터 손실 없이 학습을 완벽히 이어가도록(Resume) 만든 안전장치입니다.

## 3. 추론 코드 (`INFER_ONLY_K4.py` / `infer.py`) 핵심 로직 해설

추론 코드는 캐글 리더보드 점수와 속도를 결정지은 핵심 핵심 기법들이 들어가 있습니다.

### ① KV-Cache 복제 (`_clone_cache`) ➔ 속도 20배 가속
```python
o1 = model(**enc, use_cache=True)
base = o1.past_key_values
pkv = _clone_cache(base)
pkv.batch_repeat_interleave(b)
```
* **무슨 일을 하나요?**:
  * 4장의 이미지를 비전 엔코더에 넣어 픽셀 특징을 읽는 첫 단계 연산(`o1`)을 수행하고, 그때 만들어진 Key-Value Cache(중간 계산값 메모리)를 `base`에 저장합니다.
  * 24가지 정답 후보 순열을 채점할 때, 이미지를 다시 포워딩하지 않고 이 `base` 캐시만 $b$(배치 크기)만큼 빠르게 복사(`batch_repeat_interleave`)해서 씁니다.
* **왜 이렇게 짰나요?**: 
  * VLM 추론 연산량의 90% 이상은 이미지를 처리하는 비전 엔코더에서 나옵니다. 
  * 이미지는 1번만 계산하고 메모리를 복제해 텍스트 우도만 평가함으로써 추론 시간을 몇 시간 단위에서 단 몇 분 단위로 20배 이상 단축시켰습니다.

### ② RoPE Delta 교정 (`inner.rope_deltas`) ➔ 위치 착오 교정
```python
rd = inner.rope_deltas.item()
pos = (torch.arange(plen, plen + L, device=dev) + rd)...
```
* **무슨 일을 하나요?**: 
  * KV-Cache를 재사용하여 뒤이어 들어오는 정답 텍스트 토큰들의 위치(`position_ids`)를 계산할 때, Qwen 모델 고유의 상대적 회전 위치 임베딩 오프셋값(`rope_deltas`)을 실시간으로 가져와 수식에 더해줍니다.
* **왜 이렇게 짰나요?**: 
  * 캐시를 복제해 다층 텐서 연산을 수행할 때 RoPE 오프셋이 어긋나면 모델이 "몇 번째 글자인지" 위치를 착각해 엉뚱한 우도 점수를 뱉는 치명적인 버그가 생깁니다. 
  * 이 수식을 통해 수학적 정밀도를 완벽히 보정했습니다.

### ③ 동적 가변 청크 OOM 방어 (`try-except OutOfMemoryError`)
```python
ch = CHUNK # 초기 6
while True:
    try:
        tot = score_perm(..., ch)
        break
    except torch.cuda.OutOfMemoryError:
        torch.cuda.empty_cache()
        ch = max(2, ch // 2)
```
* **무슨 일을 하나요?**: 
  * 24개 후보 순열을 기본 6개씩(`CHUNK=6`) 쪼개어 연산하다가, 해상도가 너무 높은 이미지를 만나 VRAM 오버플로우가 터지면 코드가 죽지 않고 즉시 GPU 메모리를 청소한 뒤 청크 크기를 3이나 2로 줄여서 재시도합니다.
* **왜 이렇게 짰나요?**: 
  * 819개 테스트 문항 중 단 한 문제라도 OOM으로 에러가 나면 제출 파일(`submission.csv`)이 안 만들어지고 실격 처리됩니다. 이 코드로 100% 무조건 완주하는 방어 시스템을 구축했습니다.

### ④ 우도 K4 TTA (Test-Time Augmentation) ➔ 위치 편향 소거
```python
PERMS = [[0, 1, 2, 3], [1, 2, 3, 0], [2, 3, 0, 1], [3, 0, 1, 2]]
...
for a, s in zip(CANDS, tot.tolist()):
    score[tuple(a)] += s
```
* **무슨 일을 하나요?**: 
  * 입력 이미지의 배치 순서를 한 칸씩 회전시킨 4가지 버전(`K4`)으로 모델에 각각 집어넣고, 24개 순열에 대한 conditional log-likelihood(조건부 로그 우도) 점수를 누적 합산합니다.
* **왜 이렇게 짰나요?**:
  * VLM은 "첫 번째 자리에 있는 이미지"를 문맥과 무관하게 정답으로 선호하려는 포지션 편향(Position Bias/착시)을 강력하게 가지고 있습니다.
  * 4장의 이미지를 4번 돌려가며 각 위치에 평등하게 배치한 뒤 우도를 합산하면, 모델의 위치 착시 현상이 수학적으로 완전히 상쇄(Cancellation)되고 pure한 영상-문장 시공간 매핑 점수만 남게 됩니다. (성능 수직 상승의 핵심 수훈)

## 4. 한눈에 보는 학습 vs 추론 역할 분담표

## 5. 전체 파이프라인 구동용 오프라인 헬퍼 스크립트 해설

최종 Kaggle 학습/추론 코드가 가볍고 빠르게 구동될 수 있도록, 사전에 데이터셋을 정제하고 통계적 수치를 도출해 준 **저장소 내 원본 전처리 & 분석 헬퍼 스크립트**들의 동작 개념 해설입니다.

### A. 이미지 전처리 및 장면 전환 (CLIP) 스크립트

#### 1. `eda/clip_labeling_model.py` (CLIP 장면 분할 특징 추출기)
* **어떻게 작동하나요?**:
  * OpenAI의 `CLIP (ViT-B/32)` 모델의 이미지 엔코더를 메모리에 로드합니다.
  * 9,535개 비디오의 4장 이미지 간 코사인 거리($Dist = 1 - CosSim$)를 연산하여 `snu_clip_features.csv`에 기록합니다.
  * 이웃 프레임의 코사인 거리가 `0.20` 이상으로 끊기는 구간을 감지하여 안엄격(Loose Cut) 공식에 따라 장면 전환 횟수(0~3)를 자동 라벨링합니다.
* **왜 사용했나요?**: 
  * 모델 학습 데이터 빌딩 시 `hard_perm` 연산에 사용될 씬 단절 정보(`pairs`)와 가중 증강에 사용될 모호성 데이터를 사전에 확보하기 위함입니다.

#### 2. `eda/scene_cut_inspector_strict.py` (장면 판정 로컬 검수기)
* **어떻게 작동하나요?**:
  * 로컬 컴퓨터 환경에서 Tkinter나 Pygame 인터페이스를 가동하여 추출된 유사도 데이터(`snu_clip_features.csv`)와 원본 이미지를 매칭합니다.
  * 엔터(Enter) 키 입력 시마다 무작위 100개 비디오의 프레임을 화면에 띄우고, CLIP이 탐지한 장면 전환 컷의 타당성을 엔지니어가 눈으로 직접 검수할 수 있게 돕습니다.
* **왜 사용했나요?**: 
  * 알고리즘이 도출한 수치적 씬 컷(0.20 임계치)이 실제 인간의 인지적 씬 컷과 일치하는지 정밀하게 휴리스틱 검증하기 위한 도구입니다.

### B. 오픈 보케블러리 (OWL-ViT) 및 기하 물리 분석 스크립트

#### 1. `scratch/calculate_real_crop_statistics.py` (크롭 임계값 이원화 진단기)
* **어떻게 작동하나요?**:
  * Gemma-2B로 추출한 문장 속 명사를 `google/owlvit-base-patch32`에 텍스트 쿼리로 주입하여 4개 프레임의 타깃 물체 바운딩 박스를 추출하고 크롭합니다.
  * 추출된 $9,317$쌍의 크롭 이미지 간 CLIP 특징 벡터 거리를 연산하여 동일 대상의 분산과 타인의 분산을 통계적으로 스윕(Sweep)합니다.
* **왜 사용했나요?**: 
  * 물체 추적 중 딴 데로 미끄러지는 Tracker Drift의 실체를 증명하고, 이를 방어하기 위해 **로컬 크롭 CLIP 임계치 0.35**를 통계적으로 도출하기 위해 사용되었습니다.

#### 2. `scratch/diagnose_holdout_panning.py` (물리 부호 정합성 진단기)
* **어떻게 작동하나요?**:
  * 문장에 나타난 카메라 패닝(`Pan Left`) 지시어와 피사체의 $x$ 좌표 변화 기울기(Slope)를 부호 매핑(Panning=역방향 물리, Movement=순방향 물리)하여 비교합니다.
  * holdout 300셋 전체에 대해 줌(Zoom)과 수평 이동의 정합률을 연산하여 최종 출력합니다.
* **왜 사용했나요?**: 
  * 카메라와 물체 간의 물리 정합률이 60% 내외라는 것을 증명하여, 하드코딩 필터를 배제하고 **소프트 프롬프팅 가중 학습**으로 우회하게 만든 의사결정의 근거를 제공한 진단 코드입니다.

### C. 문장 분석 및 문법 구조화 스크립트

#### 1. `src/features/flag_detector.py` (시간적 모호성 분석기)
* **어떻게 작동하나요?**:
  * 정규식 단어 사전을 사용해 카메라 촬영 단서(`N1_camera`), 상적 전이 국면(`N2_phase`), 반복 동작(`N6`), 순서 묘사(`N7`) 등 7대 직교 플래그를 정량 추출합니다.
  * 추출된 플래그 가감점을 통해 문장의 시간적 모호성 정도인 `ai_score`를 계산해 냅니다.
* **왜 사용했나요?**: 
  * 자연어 문장이 가진 시공간 정렬의 난이도를 수치화하여 소프트 프롬프트 주입 및 학습 중요도 가중치를 매기는 데 사용되었습니다.

#### 2. `scripts/analyze_pipeline.py` (구문-비디오 상관관계 검정기)
* **어떻게 작동하나요?**:
  * SpaCy의 의존성 구문 분석기를 가동해 문장을 Type-1~3으로 분류합니다.
  * 이미지 Adjacent MSE로 분류된 비디오 장면 유형과의 교차표(Crosstab)를 작성하고, 카이제곱 검정과 Cramer's V 통계량을 계산합니다.
* **왜 사용했나요?**: 
  * 텍스트의 모호성과 이미지의 복잡성이 실제로 통계적 연관성(Lift)을 가지고 있는지 검증하여 파이프라인의 설계 건전성을 실증하기 위해 사용되었습니다.
